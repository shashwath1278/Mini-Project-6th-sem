“A Framework for Accurate Prediction of Plastic-Degrading Enzymes using Convolutional Neural Networks”
Dataset construction
•	Positive class: 208 PDE sequences from PlasticDB, cleaned to 182 sequences after removing proteins with nonstandard amino acids (lengths 108–914).
•	Negative class: 1,523 non PDE protein sequences taken from UniProt, selected with a custom search that explicitly excluded 20 known PDE enzyme names and manually verified to include proteins involved only in synthesis, not degradation.
•	The dataset is imbalanced (182 positive vs 1,492 negative after cleaning), motivating oversampling

Feature engineering
The paper uses six hand crafted sequence descriptors, computed mainly with the ftrCOOL R package and Biopython.
•	Autocorrelation (AAutoCor): Geary, Moran, and NMBroto autocorrelation descriptors over 8 AAindex properties; original dimension 240 per sequence.
•	KSAP (k-spaced amino acid pairs): frequencies of amino acid pairs separated by gaps up to k = 10, yielding 3,600 features per protein.
•	Conjoint Triad (CT): maps 20 amino acids to 7 classes and counts triads, producing 343 features.
•	CTD (Composition/Transition/Distribution): encodes distribution of 7 physicochemical properties (hydrophobicity, volume, polarity, etc.), dimension 148.
•	DDE (Dipeptide Deviation from Expected mean): compares observed dipeptide frequencies with theoretical mean and variance based on codon usage, 400 features.
•	Secondary structure (helix, turn, sheet): 3 features extracted via Biopython.
Feature selection and dimensionality reduction

They evaluate three strategies: ANOVA, ANOVA + Permutation Feature Importance (PFI), and ANOVA + XGBoost feature importance.
•	Across five different feature-set combinations, ANOVA + XGBoost consistently gives the best performance (slightly higher F1, ROC, MCC).
•	This hybrid method dramatically reduces feature dimensionality:
o	Autocorrelation: 240 → 136
o	DDE: 400 → 108
o	CTD: 148 → 38
o	KSAP: 3,600 → 109
o	Conjoint Triad: 343 → 137
o	Secondary structure: 3 → 3 (unchanged)
•	Dimension reduction is argued to mitigate overfitting and reduce computational cost while maintaining accuracy.

•	Handling class imbalance
•	They use SMOTE with sampling_strategy = "minority" to oversample the positive (PDE) class and balance the dataset.
•	A comparison (reported in supplementary file S5) shows that models trained on SMOTE balanced data generalize better than those trained on imbalanced data.
Model architectures and training
Seven supervised models are tested: CNN, Random Forest, Feedforward NN (“Basic Neural Network”), Logistic Regression, Naive Bayes, KNN, and XGBoost.
The final CNN architecture:
•	Input: selected feature vectors (various feature sets).
•	5 convolutional layers with kernel size 1, leakyReLU activation, batch normalization, zero-padding, and max‑pooling.
•	Parameters initialized with He initialization; L1 kernel regularization with strength 0.001; dropout 0.2 in hidden layers; trained for 74 epochs using Adam and binary cross‑entropy.

•	3 fully connected hidden layers with 128 units and ReLU; final dense layer with 2 neurons and sigmoid activation for binary classification.

CNN is selected because it achieves the best performance among all models on the tuned feature set.

Feature-set evaluation
They form five feature-set combinations (F1–F5) by mixing the six descriptors in different ways; for example, Feature Set 4 = KSAP + CT + DDE + Autocorrelation + Secondary Structure.
After applying ANOVA + XGBoost feature selection, Feature Set 4 with the CNN gives the best F1 and ROC.
Autocorrelation emerges as the most influential descriptor: removing it significantly drops performance, followed by KSAP, CTD, and DDE.
Best-reported performance
CNN on Feature Set 4 achieves:
Accuracy ≈ 0.96
F1 score ≈ 0.80
ROC-AUC ≈ 0.96
MCC ≈ 0.77
Precision ≈ 0.86.
Other models reach F1 in roughly the 0.57–0.77 range, confirming the advantage of CNN with the chosen features.

Limitations
1.	Small and Imbalanced Dataset

The positive dataset had only 182 plastic-degrading enzyme sequences versus 1,523 non-PDE sequences. Even with SMOTE, synthetic samples don't fully capture the true biological diversity of PDEs.

How to fix it: Expand the positive dataset by mining additional databases like PMBD and CAZy alongside PlasticDB. You could also apply data augmentation techniques specific to protein sequences — such as back-translation (converting sequences to codons and back) or using protein language models like ESM-2 to generate biologically plausible sequence variants. Transfer learning from pre-trained protein embeddings would also reduce dependence on dataset size.


2.	Heavy reliance on handcrafted features, no modern embeddings
The framework extracts features exclusively through six hand-engineered biochemical descriptors — Autocorrelation, KSAP, CTD, DDE, Conjoint Triad, and Secondary Structure. While these are biologically motivated, they represent a fixed, human-curated compression of sequence information. Whatever patterns these descriptors fail to encode are permanently lost before the CNN ever processes the data. The paper makes no attempt to incorporate protein language model (PLM) embeddings, which have become the dominant feature representation strategy in modern computational biology. This is a significant gap given that the paper's stated goal is discovering novel PDEs from environmental sequences — precisely the scenario where richer, more generalizable representations matter most.

Use a pre-trained PLM such as ESM-2 (Meta AI) or ProtBERT to generate dense vector representations for each protein sequence. These models have been trained on hundreds of millions of protein sequences via self-supervised learning and implicitly encode evolutionary conservation, functional motifs, and structural tendencies without any manual feature engineering.
For each protein in the dataset, pass the amino acid sequence through the PLM and extract the per-sequence embedding (typically the mean-pooled representation across all residue positions). This gives you a fixed-length vector per protein that serves as a direct drop-in replacement or supplement for the handcrafted feature vectors.
3.	Sequence-Only Feature Extraction (No Structural/Evolutionary Context)
All six descriptors (AAutoCor, KSAP, DDE, CTD, Conjoint Triad, Secondary Structure) are derived purely from primary sequence composition. They don't capture 3D structural context or evolutionary relationships, which are critical for enzyme function.
How to fix it: Integrate structure-aware features using AlphaFold2-predicted structures to extract geometric and physicochemical surface features. Supplement with evolutionary features like Position-Specific Scoring Matrices (PSSMs) from PSI-BLAST, or use pre-trained transformer embeddings (ESM-2, ProtT5) as feature inputs, which encode evolutionary information learned from millions of sequences.

4.	. Binary Classification Without Plastic-Type Specificity
The model performs only binary classification:
PDE vs. Non-PDE
without distinguishing the specific plastic substrate degraded by the enzyme. However, practical biodegradation applications require identifying enzymes specialized for particular plastics such as:
•	PET 
•	PE 
•	PU 
•	PS 
•	PVC 
A general PDE prediction provides limited functional insight for industrial enzyme engineering and environmental deployment.
How to fix it
Reformulate the task as:
•	multi-class classification
OR 
•	multi-label prediction 
using substrate-specific annotations from PlasticDB and related databases.
A hierarchical framework can also be used:
1.	PDE vs Non-PDE 
2.	Plastic substrate prediction 
Transformer-based architectures or graph neural networks can model enzyme–substrate specificity more effectively.
